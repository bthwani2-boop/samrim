## 1. Activation rule

This profile is **conditional**, not a mandatory pre-Product phase.

Activate it only when exact-current diagnosis proves missing/invalid non-semantic substrate blocks the authorized outcome or when explicit `FULL_TARGET` requires repository-wide substrate convergence.

~~~text
SUBSTRATE WORK WITHOUT CURRENT CAUSAL REQUIREMENT = FORBIDDEN
EMPTY FUTURE LANES = FORBIDDEN
SPECULATIVE PRODUCT FURNISHING = FORBIDDEN
~~~

Durable substrate meaning belongs to `governance/architecture/PLATFORM-SUBSTRATE.md`.

## 2. Permitted structural work

Only materially required substrate, such as:

- repository/workspace/toolchain repair;
- deployable host shell/runtime identity required by an active consumer;
- admitted service process startup/health/readiness;
- contract/client/database/migration/test lane only when a real current responsibility uses it;
- runtime/infra composition required for proof;
- developer launcher/bootstrap/doctor needed by current workflow;
- proven reusable Design-System/technical package required by current consumers;
- durable guards only when they enforce a unique current invariant.

## 3. Forbidden work

~~~text
EMPTY SERVICE/CONTRACT/CLIENT/DATABASE/TEST LANES
FAKE BUSINESS ROUTES/SCREENS/ENDPOINTS/TABLES
CAPABILITY-SPECIFIC STATE MACHINES OUTSIDE AN AUTHORIZED CAPABILITY
FUTURE NAVIGATION/TABS
DONOR FEATURE TREE COPYING
GENERIC FRAMEWORKS WITHOUT CURRENT CONSUMERS
~~~

## 4. Completion interface

The structural root is complete only when the exact affected cone conforms to applicable platform-substrate/topology/runtime/policy owners, required runtime/build evidence passes, losing structure is removed, and no speculative lane was created.

Verification is owned by `../verify/structural-conformance.md`. There is no global substrate gate that all future Product work must pass.
