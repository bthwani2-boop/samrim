# DSH owner-bound clients

STATUS: IMPLEMENTATION_IN_PROGRESS

The exact method/path index at `clients/generated/dsh-operations.ts` is generated from this owner's executable OpenAPI fragments and used by public discovery transport. `pnpm check:contracts` checks for missing or stale generated output without rewriting it. Run `node tools/dev/generate-openapi-operations.mjs dsh` only after reviewing an approved owner-contract change. This is method/path parity; complete schema/error/authentication/runtime parity and end-user checkout acceptance remain separate gates.

The private `@bthwani/dsh` workspace package exports read-only public Store/Offer projections and opt-in private Store operational GET/PATCH clients. Their sole source contract is `services/dsh/contracts/openapi/dsh.openapi.yaml`, including `paths/store-access.yaml` and `paths/operational-policies.yaml`. City policy GET/PATCH require the current Identity `platform_policies` permission, and the server alone versions and audits approved DSH city limits. The client does not persist policy state or become its writer. The private client requires a current Identity bearer per invocation; it never stores credentials, grants Store rights, writes business facts itself, or treats discovery as checkout authorization. Server-side DSH remains the only Store writer. TypeScript validation and an exported client are not evidence of active Merchant/Operator Web/Android UX.

Local isolated tests exercise the running Go DSH owner against PostgreSQL. For a private Store PATCH, an unreachable network, cancelled in-flight request or malformed success response returns `OPERATION_RESULT_UNKNOWN`: the operation **may already be committed**. The caller must retain the **same** `operationId`, read back the canonical Store availability, and reconcile or replay the same operation rather than inventing a new one. No automatic unsafe retry is implemented in the client. A failed GET remains `OWNER_NETWORK_UNAVAILABLE`. When a caller aborts the request because the active Store/account changes, a late but successful GET is rejected as `OWNER_RESPONSE_STALE`; a late PATCH success is conservatively `OPERATION_RESULT_UNKNOWN` and must never be shown as a successful update to the new account. Consumers must abort their prior view's signal on Store/account switches and reconcile any ambiguous write with the original operation key. Android, production, historical Store migration, checkout, full generated OpenAPI client parity and actual Operator Web/Android UX have **not** been established by package typecheck. Isolated real Identity/DSH/PostgreSQL policy-read authorization is a separate service test, not an end-user acceptance test. Only supported scopes may be shown as operational.

The public Store/Vertical/Offer discovery transport and response validators live in `clients/public-discovery.ts`. Shared endpoint safety, object-key checks and the single `DshPublicError` class live in `clients/client-core.ts`, so private client modules do not depend on public-discovery code. `clients/index.ts` preserves the published `@bthwani/dsh` exports without exposing internal helpers as package subpaths. Private Store availability, city policies and Operator Captain review now reside in `clients/store-availability.ts`, `clients/city-policies.ts` and `clients/operator-captains.ts`. Their authenticated HTTP transport is shared only inside the owner package through `clients/private-owner-request.ts`, which accepts per-request bearer credentials and preserves ambiguous PATCH results. `clients/index.ts` is the single public entrypoint, not another transport implementation. This is an organization change, not additional discovery authority or completed checkout acceptance.

Merchant Store standing (`GET /v1/stores/mine`) is owned by `clients/merchant-standing.ts` and exported from `@bthwani/dsh`. The Merchant `src/features/access/dsh-standing.ts` file is a compatibility re-export only; it must not perform fetch or maintain separate Store DTO parsing. The caller supplies the current Identity bearer and abort signal for each read. Owner denial, stale responses and malformed payloads remain fail-closed. These transport tests do not alone prove complete Merchant Web/Android admission or SQL behavior.

Do not fork transport DTOs elsewhere, add another Store writer, copy the donor implementation wholesale, or introduce a client-side business policy interpreter. Generate contract-derived client code at the owner when source implementation is accepted.
