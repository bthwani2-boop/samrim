## 5. أسس التصميم والتقنية المعتمدة

- لا تثبيت حزم أو ترقيات أو أطر جديدة في مرحلة التأسيس، بل استخدام الموجود والنسخ المثبتة في lockfiles، وإعادة ربط المخازن المحلية عند الحاجة بإذن منفصل إذا تعذر الاستعمال المباشر. لا نسخ node_modules المولدة إلى Git.
- Expo: app-client وapp-partner وapp-captain فقط حسب النطاق المعتمد. Expo Web الخاص بالعميل يملك العرض الكامل للمتجر؛ لا تطبيق متجر مستقل ولا Checkout جديد بسبب نوع العلاقة.
- Tamagui: packages/tamagui-config هو أساس عناصر العرض/المكونات المناسبة؛ القيم الدلالية للعلامة والثيم مصدر واحد لا نسختان. design-system القديم يُنقل منه ما ثبتت قيمته: خرائط ومحادثات ووسائط وإشعارات/نوافذ عند ملاءمة المالك، دون إنشاء مكونات عامة منافسة.
- Control Panel: Next.js + Ant Design القائم، يُوائم هوية Tamagui البصرية عبر قيم مشتقة، لا عبر كاتب Theme مستقل.
- Identity وDSH وWLT: ملاك خدمة منفصلون بعقود واضحة، مع عدم استدعاء SQL خدمة أخرى للقرار التجاري وعدم تخزين الكاتب نفسه في أكثر من مكان.
- SQL: استخراج الحقائق من كل هجرات المصدر وقراءة المخطط الدائم، ثم Baseline جديد واحد قانوني لكل مالك مع مسار Safe Upgrade منفصل للمحميات؛ لا نقل SQL القديم إلى الشجرة الجديدة على أنه تنفيذ معتمد.
- Docker: ملفات تعريف نظيفة، مشروع Compose منفصل، شبكات ومنافذ وVolumes جديدة ومعزولة، مع إعادة استخدام الصور القائمة المناسبة. لا Docker down/prune/volume rm للبيئة القديمة.
- CI: إعادة استخدام Fast Guard وSonar وCodeQL الموجودين، وتقوية التوجيه وفحص ملكية المصادر والمخطط والتكامل. CI لا يحذف الملفات ولا يعد اختبارًا بديلًا عن تنفيذ الخدمة الفعلية.

## 8. قواعد المخاطر العالية غير القابلة للتفاوض

- Identity: منع IDOR بين مستخدمين ومتاجر ومشغلين، تبديل الحساب مع طلبات معلقة، إبطال وتدوير الجلسة واستعادة الدخول دون Root Owner بديل.
- DSH: لا سعر عميل معتمد، حالات الطلب قانونية، Store وOffer متاحان وقت التأكيد، عدم تكرار Order عند Retry أو سباق، الحفاظ على العنوان مخفيًا حتى الأهلية، وعدم قبول عرض توصيل مرتين.
- WLT: دفاتر متوازنة وقيود Exactly-once بالمعنى التجاري، كشف التسويات، تخصيص دفع Wallet/COD/Mixed، لا خصم مكرر ولا تحصيل اشتراك قبل جاهزية الفوترة والموافقة، فصل إنشاء الطلب عن العملية المالية بما يضمن التعافي بعد الفشل.
- SQL: قيود CHECK/UNIQUE/FK، فهارس مثبتة بالحاجة، أعمدة وأحداث مرجعية، RLS/ACL عند انطباقها، أحجام الاختبار واستعادة النسخة، فصل صلاحيات Runtime/Migrate.
- التشغيل: لا مشاركة Volumes PostgreSQL/SeaweedFS بين القديم والجديد؛ لا نشر أو نقل بيانات دون تفويض ومراجعة استعادة.
- الأسرار: لا .env حقيقي ولا token/password في Git أو الخطة أو حزم الإثبات. اقرأ أقل قدر لازم فقط وأخفِ القيم.
