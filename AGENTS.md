## 7. Git delivery

Every executor delivers each coherent owned tested foundation immediately, not at the end of a campaign. Standing or specific human Push authority permits normal fast-forward only to the existing authorized unprotected development upstream. Unrelated dirty files, unpublished changes and peer tests are not general blockers; never require a globally clean worktree, all peers to finish, or a delivery reservation. Verify actual repository, remote, branch, upstream, protections/rulesets, remote SHA, index, relevant writers, all outgoing commits, publication authority, secret checks, tests and diff. Do not infer authority for main, protected branches, archive/**, another remote, Force Push, new Branch/Worktree/PR, Merge, deployment or release.

1. Record the reviewed base and exact owned tested path/blob inventory. Use native path-scoped Git staging/commit; verify the index, UTF-8, exact candidate and diff. Commit only owned paths immediately; native path-limited commit is permitted when the actual candidate is verified and unrelated staged/unstaged work is preserved. Do not stage others' paths or commit unapproved index entries. No blanket git add, empty commit, Reset/Rebase/Stash or rewriting history to displace peer work.
2. Read and freeze the full immutable verified commit SHA. Verify parent, exact committed files/blobs and all outgoing ancestors relative to the actual remote. Reconcile actual conflicting writes without a coordinator, dedicated reservation, lock or wrapper. A changed symbolic HEAD or moving ref is not authorization to include more commits.
3. Push the **immutable full commit SHA**, never symbolic HEAD or a moving local branch ref: git push <verified-remote> <verified-full-commit-sha>:refs/heads/<verified-upstream-branch>. Use the actual verified values, ordinary fast-forward and no force. Reconcile material changes to HEAD, index, remote, candidate or authorization without imposing a global cleanliness requirement. Unapproved outgoing ancestors or non-fast-forward block that affected Push only; preserve the owned tested work and resolve the actual conflict without rewriting peer history.
4. Read back the actual remote SHA and committed content; if a subsequent authorized advancement occurred, prove ancestry and unchanged relevant blobs rather than falsely claim equality. Verify preservation of peer changes and index entries. Reconcile an ambiguous effect before retry. No administrative release step; keep independent work moving.
5. Inspect required CI/security/quality on the exact published candidate; pending, failed or unavailable mandatory proof keeps the affected acceptance open. Publication is delivery, not acceptance. Retain valid proof and rerun affected and mandatory direct checks; do not freeze unrelated safe work or assume journey, governance or production readiness.
