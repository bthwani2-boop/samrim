## 7. Git delivery

Deliver each coherent owned tested foundation immediately, not at the end of the campaign. Standing or specific human Push authority permits normal fast-forward only to the existing authorized unprotected development upstream. Verify live repository, remote, branch, upstream, protections/rulesets, remote SHA, index, active writers, all outgoing commits, ownership/publication authorization, secret checks, tests and diff. Do not infer authority for main, protected branches, archive/**, another remote, Force Push, new Branch/Worktree/PR, Merge, deployment or release.

1. Record the reviewed base and exact owned tested path/blob inventory. Stage only those paths, confirm the index, UTF-8 and staged diff, then make the local Commit immediately. No blind git add . / git add -A, empty commit, Reset/Rebase/Stash or history rewriting to erase other work.
2. Read and freeze the complete verified commit SHA. Confirm its parent, exact committed files/blobs and every outgoing ancestor relative to the current remote. Use direct native Git with no administrative delivery reservation; reconcile real conflicting operations before proceeding. A later change to symbolic HEAD or a local branch name is not an approved addition to the tested batch.
3. Push the **immutable full commit SHA**, never symbolic HEAD or a moving local branch ref: `git push <verified-remote> <verified-full-commit-sha>:refs/heads/<verified-upstream-branch>`. Use actual verified values, ordinary fast-forward and no force. If HEAD/index/remote or authorization changes, reconcile the exact batch and actual durable effects before deciding whether to proceed. A non-fast-forward or ambiguity is not permission to include unapproved ancestors, change destination, overwrite or blindly retry.
4. Read back the actual remote SHA and exact committed content. If a subsequent authorized remote advancement occurred, verify the delivered commit's ancestry and unchanged relevant blobs rather than falsely claim equality. No administrative release step is required; reconcile the index and durable outcome before continuing. Keep tested local work if safeguards cannot be proven.
5. Inspect required CI/security/quality on the exact published SHA. Pending, failed or unavailable mandatory proof keeps the affected scope open. Publication is delivery, not acceptance; do not freeze unrelated safe work or assume governance cutover or production readiness.
